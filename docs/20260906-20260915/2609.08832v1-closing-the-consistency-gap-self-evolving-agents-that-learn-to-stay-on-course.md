## 摘要
由大语言模型（LLM）驱动的智能体平均而言可能准确，但在生产环境中却不可靠；这一差异已被观察到，但很大程度上仍未得到解决。在 AppWorld 基准上使用 GPT-4.1 的 ReAct 智能体，当同一任务被给予五次时，五次运行全部成功的比例仅为 53%，尽管其单次运行通过率平均为 77%。我们将这 24 个百分点的缺口称为一致性差距，并认为解决这一差距是可信赖 AI 智能体部署的前提条件。我们提出一种自进化智能体框架，通过识别智能体轨迹中不稳定、低一致性的步骤，并将其转化为智能体在未来运行中可借鉴的情景记忆，来缩小这一差距。其核心是一个一致性分析器，用于精确定位轨迹在多次执行中可能发生翻转的位置及原因；以及一个指南生成器，用于将诊断结果转化为有针对性的指南，写入记忆，并在未来相似任务的智能体执行中注入。在 AppWorld 上，使用 ReAct/GPT-4.1 时，我们的框架在相同任务评估中将五次运行全部成功的任务比例提高了 16 个百分点，在相似任务泛化中提高了 13 个百分点。

## Abstract
Large language model (LLM)-powered agents can be accurate on average yet unreliable in production, a discrepancy that has been observed but remains largely unaddressed. When given the same task five times, a ReAct agent on the AppWorld benchmark using GPT-4.1 succeeds in all five runs only 53% of the time, even though its per-run pass rate averages 77%. We call this 24-point shortfall the consistency gap, and we argue that addressing it is a precondition for trustworthy AI agent deployment. We present a self-evolving agent framework that reduces this gap by identifying unstable, low-consistency steps in agent trajectories and converting them into episodic memory the agent can draw on in future runs. At its core is a Consistency Analyzer that pinpoints where and why a trajectory is likely to flip across executions, and a Guideline Generator that converts the diagnosis into targeted guidelines, committed to memory and injected into future agent executions on similar tasks. On AppWorld with ReAct/GPT-4.1, our framework raises the fraction of tasks that succeed in all five runs by +16 points on same-task evaluation and +13 points on similar-task generalization.

## 1. 核心问题与研究动机

- **核心问题：LLM 智能体的“一致性缺口”（Consistency Gap）**。智能体在平均准确率上表现尚可，但在生产环境中并不可靠——同一任务、同一智能体、同一模型，多次运行会得到不同结果。
- **量化证据**：在 AppWorld 基准的 168 任务 test normal 划分上，ReAct + GPT-4.1 的单次平均通过率（Mean@5）为 **77%**，但五次运行全部通过（Pass^5）的任务仅占 **53%**，缺口达 **24.4 个百分点**。GPT-OSS-120B 更严重：Mean@5 为 33.9%，Pass^5 仅 10.1%（缺口 23.8 pp）。
- **关键论点**：一致性 ≠ 准确率。高平均通过率可以与低一致通过率并存；标准 benchmark 准确率数字无法反映部署用户实际体验。作者认为缩小一致性缺口是可信 AI 智能体部署的**前提条件**。
- **三条设计观察**：
  1. 一致性需作为一等目标，需专门指标（Mean@k vs Pass^k）、估计机制与针对性干预手段；
  2. 不一致性有可测量的 token 级指纹——平坦的下一 token 分布使决策在温度为零解码下仍会翻转，可通过重采样测量响应变异性来估计；
  3. 可在 prompt 层面注入一致性指南来稳定推理点，不触及推理循环、与智能体架构无关、且限于离线分析阶段。

## 2. 方法论

### 2.1 整体框架：两阶段离线流水线（Detect + Generate）

- **操作循环**：执行用户任务，可选注入从记忆检索的指南，观测层捕获完整轨迹。
- **离线分析循环**：将每条捕获轨迹转化为新指南，写入情景记忆，供未来相似任务检索。两个循环构成自进化闭环。
- 构建于 Fang et al. (2026) 的轨迹信息记忆框架之上（存储、聚类、去重、合并、检索机制不变），贡献在于新增“**面向一致性而非仅面向结果**”的上游抽取阶段。

### 2.2 一致性指标定义

- **Pass@k**：k 次中至少成功一次（隔离能力与采样噪声）。
- **Mean@k**：每任务平均通过率（标准报告精度）。
- **Pass^k**：k 次全部成功（隔离一致性）。
- **一致性缺口**：`Gap@k(T) = Mean@k(T) − Pass^k(T)`，单位为百分点。
- **归一化一致性**：`Consistency@k(T) = Pass^k(T) / Mean@k(T) ∈ [0,1]`，消除能力上限混杂；由此 `Gap@k = Mean@k · (1 − Consistency@k)`。

### 2.3 一致性分析器（Consistency Analyzer）

- **黑盒特性**：仅用记录的 prompt 重新调用底层 LLM，不访问 logits、内部激活或智能体源码，适用于任何托管 LLM 端点。
- **为何贪心解码不够**：平坦分布对 GPU 浮点噪声、批处理、tokenizer 状态等平台噪声敏感，微扰即可改变 top token；单次响应的置信度只反映所选路径的深度，不反映次优 token 的接近程度。因此需通过**重采样**估计分布形状。
- **步骤一致性度量**（对每个推理步骤 s_i 重采样 N 次，默认 N=30，温度 ≤ 0.5）：
  - **自由文本/代码**：SBERT 句/代码嵌入的**平均成对余弦相似度**（公式 4），容忍改写与语义等价代码。
  - **分类响应**（工具名、枚举参数、结构化标识符）：token 集合上的**平均成对 Jaccard 相似度**（公式 5），惩罚任何 token 级不匹配。
  - **结构化组合响应**（如含 thoughts 与 action/action input 的 JSON）：按字段分解，每个字段映射到上述基元类型，再做**加权和**（公式 6，权重 δ_f 可配置，置零可抑制无关字段）。
- **轨迹一致性聚合**：`C_mean(T) = (1/n) Σ C(s_i)`。局限是视步骤独立，不惩罚依赖上游低一致性决策的高一致性步骤。

### 2.4 指南生成器（Guideline Generator）

- **触发条件**：步骤一致性 `C(s_i) < θ_C`（默认 **θ_C = 0.85**）且位于智能体决策路径上。
- **指南分类**（沿用 Fang et al. 2026 的分类法并适配一致性目标）：
  - **strategy（策略）**：对虽高变异但结果正确的模式加以固化（智能体“猜对了”）；
  - **recovery（恢复）**：绕开其变异性与失败相关的步骤；
  - **optimization（优化）**：跳过或简化非必需的高变异步骤。
- **流程**：带标记的轨迹与记分卡交给 LLM 生成器，生成针对性指南，进入双索引情景记忆（嵌入 + 类别/优先级/上下文/任务类别/来源元数据），运行时按余弦相似度或 LLM 引导选择器检索。
- **关键差异**：一个“成功但高响应变异性”的步骤与一个“可观察失败”的步骤**同样有资格**生成指南。

## 6. 主要结论与发现

- **同任务一致性提升**：
  - GPT-4.1：Pass^5 **+16.0 pp**（53.0% → 69.0%，相对提升 30%），Mean@5 **+3.6 pp**（无退化），归一化一致性 **+0.17**；Medium 绝对增益最大（+22.9 pp），Hard 相对增益最大（+14.3 pp，相对 45%）。

- **相似任务泛化**：
  - GPT-4.1：Pass^5 **+13.0 pp**（仅比同任务低 3 pp）；GPT-OSS-120B：Pass^5 **+8.7 pp**，甚至**超过**其同任务增益（+6.0 pp），Hard 归一化一致性从 0.00 升至 0.29。
- **一致性缺口缩小但未消除**：GPT-4.1 聚合缺口从 0.32 降至 0.15（缩小 53%）；GPT-OSS-120B 从 0.70 降至 0.58，受限于其低原始能力。
- **分析器的预测能力**：聚合轨迹一致性作为轨迹通过/失败的分类器，**AUROC = 0.699**，可作为无真实评分环境下生成器判断轨迹结果的辅助信号。
- **总体判断**：一致性定向的情景记忆指南可在不损害平均准确率的前提下提升重复运行可靠性，并具备跨相似任务的迁移能力。

## 7. 优点

- **问题定义清晰且具实践价值**：将“一致性缺口”形式化为 Mean@k − Pass^k，并提出归一化一致性 Consistency@k 以消除能力上限混杂，指标设计严谨。
- **黑盒、架构无关**：分析器只需重新调用托管 LLM 端点，不依赖 logits 或智能体源码；指南注入仅作用于 prompt 层，不修改推理循环，便于落地。
- **语义感知的度量设计**：用 SBERT 嵌入相似度容忍改写与功能等价代码，用 Jaccard 捕捉需精确匹配的分类字段，并用结构化组合公式处理半结构化响应，兼顾鲁棒性与敏感性。
- **“成功但高变异”步骤同样可生成指南**：区别于仅从失败中学习的记忆框架，能固化“猜对了”的正确模式。
- **两阶段离线流水线 + 自进化闭环**：Detect 与 Generate 均在离线执行，不增加运行时推理开销；指南积累形成正反馈动态。
- **实验覆盖同任务与相似任务两个层次**，并在两个能力差异大的模型上验证，附录给出完整分难度数据，透明度较好。
- **开源贡献**：代码已发布于 `github.com/AgentToolkit/altk-evolve`。
- **明确指出局限**：包括平台非确定性不可控、分析器只评分稳定性不评分正确性、重采样成本等，学术态度诚实。

- **记忆增长与指南冲突未讨论**：随着指南持续积累，检索可能返回相互冲突或过时的指南，缺少遗忘、更新与冲突消解机制的说明。

## 9. 总体评价与定位

- **贡献定位**：本文的核心贡献不在新智能体架构，而在于**把一个被普遍忽视的部署可靠性问题形式化**（一致性缺口 = Mean@k − Pass^k），并给出一个黑盒、架构无关、prompt 层可落地的缓解方案。这一"指标 + 诊断 + 干预"的三段式结构，本身即可作为后续一致性研究的参考范式。
- **方法论价值**：用重采样分布形状（而非单次响应的置信度）来刻画决策稳定性，抓住了"平坦下一 token 分布"这一被忽略的不一致来源，是对"温度为零即确定性"这一常见误解的有力纠正。
- **证据强度**：在两个能力差异显著的模型（GPT-4.1 与 GPT-OSS-120B）上取得一致的 Pass^5 提升且 Mean@5 无退化，是相对可信的信号；相似任务迁移增益接近甚至超过同任务增益，说明指南捕捉到的是可复用的模式而非任务特定的记忆。
- **结论边界**：所报告的一致性提升是**部分缓解**而非消除，且提升幅度高度依赖基线能力（低能力模型缺口仍达 0.58）；因此本文更应被读作"证明该问题可被系统性干预"的存在性论证，而非"已解决一致性"的终局方案。
- **实践启示**：对部署方而言，报告 Mean@k 会系统性高估用户体验，Pass^k 或归一化一致性应成为智能体发布前的常规指标；对研究者而言，一致性可作为与准确率并列的一等优化目标，纳入记忆、规划与工具调用各环节。

## 10. 后续研究建议（基于本文局限）

1. 在多个 benchmark 上复现，检验一致性缺口的普适性与指南方法的可迁移性；
2. 引入自适应重采样与早期停止，量化 N 与增益的边际收益曲线；
3. 将一致性信号与正确性验证器结合，避免"自信地错误"被误判为稳定；
4. 与 self-consistency、语义熵等推理时基线做同条件对比；
5. 用独立模型或人工评估替代自我评判，降低指南生成的偏差；
6. 建模步骤间依赖，从轨迹级而非步骤级定义一致性；
7. 研究指南的遗忘、冲突消解与有害指南回滚机制。
