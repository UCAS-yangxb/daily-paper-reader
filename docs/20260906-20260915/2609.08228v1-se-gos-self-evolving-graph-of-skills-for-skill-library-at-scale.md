## 摘要
现代 LLM 智能体日益依赖可复用技能，然而当技能库扩展到数千条目时，有效检索成为瓶颈。Graph-of-Skills（GoS）通过利用依赖感知的图结构进行可扩展技能检索来应对这一挑战，而 SkillDAG 进一步表明，技能图可以在线积累由执行证据支撑的结构。然而，这些方法仍未回答：历史执行轨迹能否被系统地提炼为一个更好的、可泛化到未见任务的检索图。我们提出自演化技能图（Self-Evolving Graph-of-Skills，SE-GoS），一个无需训练的框架，可从执行轨迹中演化现有 GoS 图，同时保留原始检索流程。SE-GoS 执行三种互补更新：拓扑演化，从执行证据中发现并修剪技能关系；边权演化，基于历史有效性强化与检索相关的关系；描述演化，利用执行反馈优化面向检索的技能描述。在 SkillsBench 上使用三个 LLM 的实验中，SE-GoS 持续提升任务奖励，同时相对于完整技能加载减少输入 token，且增益因模型系列而异。在一个代表性设置中，一轮演化将奖励从 52.4% 提升至 59.4%，同时相对于完整技能加载减少约三分之一的输入 token，且所得图可迁移到一个不相交的留出划分，相比静态 GoS 基线提升 5.4 个百分点。这些结果表明，技能图可以从执行经验中得到改进，而无需模型训练、更改检索算法或修改技能内容，从而将静态检索图转变为不断演化的检索基础设施。

## Abstract
Modern LLM agents increasingly rely on reusable skills, yet as skill libraries scale to thousands of entries, effective retrieval becomes a bottleneck. Graph-of-Skills (GoS) addresses this challenge by exploiting dependency-aware graph structure for scalable skill retrieval, while SkillDAG further demonstrates that skill graphs can accumulate execution-backed structure online. However, these approaches leave open whether historical execution traces can be systematically distilled into a better retrieval graph that generalizes to unseen tasks. We present Self-Evolving Graph-of-Skills (SE-GoS), a training-free framework that evolves an existing GoS graph from execution traces while preserving the original retrieval pipeline. SE-GoS performs three complementary updates: topology evolution that discovers and prunes skill relationships from execution evidence, edge-weight evolution that reinforces retrieval-relevant relationships based on historical effectiveness, and description evolution that optimizes retrieval-facing skill descriptions using execution feedback. Across three LLMs on SkillsBench, SE-GoS consistently improves task reward while reducing input tokens relative to full skill loading, with gains varying across model families. In a representative setting, one evolution round improves reward from 52.4\% to 59.4\% while reducing input tokens by approximately one-third relative to full skill loading, and the resulting graph transfers to a disjoint held-out split with a 5.4-point improvement over the static GoS baseline. These results show that skill graphs can be improved from execution experience without model training, changes to the retrieval algorithm, or modifications to skill content, turning a static retrieval graph into an evolving retrieval infrastructure.

# SE-GoS 论文总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体越来越多地依赖可复用技能。当技能库从几十条扩展到上千条时，瓶颈从“是否使用技能”转向“如何检索到足够且必要的技能子集”。
- **现有方法的问题**：
  - 全量加载技能库 token 成本线性增长，且模型容易在超长上下文中忽略关键技能。
  - 向量检索偏向语义相似，忽略功能前置依赖，容易召回高层技能却漏掉底层解析、配置等必要工具。
  - Graph-of-Skills（GoS）通过类型化有向技能图与 reverse-aware PPR 做依赖感知检索，但图是**静态**的：构图后不再根据执行反馈更新。
  - SkillDAG 虽能在线上积累执行支撑的结构，但其冷启动和结构判断依赖 LLM/embedding，且未系统回答“历史执行轨迹能否蒸馏为可泛化到未见任务的检索图”。
- **核心问题**：能否在不训练模型、不修改检索算法、不编辑技能内容的前提下，把执行轨迹中的“免费信号”——哪些技能被检索、哪些被实际使用、任务是否成功——系统性地蒸馏进检索图，使静态技能图演化为可积累经验的检索基础设施。
- **整体含义**：论文主张经验应存放在**检索 harness / 技能图**中，而非模型参数或技能文本中。这样更新成本低、可审计、可逆，并可被多个智能体共享。

## 2. 方法论

### 2.1 核心思想

- SE-GoS 是一个**免训练**框架，保留原 GoS 检索流程不变，仅演化其读取的图与节点描述。
- 冷启动图不是 GoS 的完整类型化图，而是**确定性 semantic-only 相似图**：每个技能按 signature-token overlap 连接 top-k 最近邻，不需要 LLM 关系验证器，也不需要 embedding 服务。
- 执行反馈提供缺失结构：workflow、dependency、avoid 边由真实轨迹中的“检索—使用”模式学习得到，而非 LLM 对技能相关性的先验判断。
- 检索阶段直接读取图的边权与描述，因此重连边、改边权、改描述会改变 PPR 分数与最终召回，而检索代码保持固定消费者角色。

### 2.2 关键技术细节

- **图与关系定义**：  
  \(G=(V,E,w,\phi)\)，关系集 \(R=\{\text{dep},\text{wf},\text{sem},\text{alt}\}\)，分别表示依赖、工作流、语义、替代关系。SE-GoS 只诱导 dep、wf、avoid，不诱导 alt，因为替代性是反事实判断，观测轨迹无法认证。

- **检索流程不变**：
  - 种子分数：\(z_i(q)=\xi s_i^{sem}(q)+(1-\xi)s_i^{lex}(q)\)，实验中设 \(\xi=0\)，即纯词法种子。
  - 归一化种子分布：\(p_i=z_i(q)/\sum_j z_j(q)\)。
  - 类型化反向感知扩散：  
    \(T=\text{RowNorm}\left(\sum_{r\in R}\lambda_r(T_r^{\rightarrow}+\gamma_r T_r^{\leftarrow})\right)\)。
  - PPR 迭代：\(s^{(\ell+1)}=\alpha p+(1-\alpha)T^\top s^{(\ell)}\)。
  - 重排与预算化 hydration：\(\rho_i(q)=s_i^\star+\mu m_i(q)\)。

- **三类互补更新**：

  - **拓扑演化（改边集 \(E\)）**：
    - **Workflow 边**：成功 trial 中，若检索种子技能 \(u\) 与被使用技能 \(v\) 共现，则加边 \(u\to v\)。权重为  
      \(w_{wf}(u\to v)=\min(0.9,0.6+0.05(c_{uv}-1))\)，一次成功共现即连边，重复增强但设上限。
    - **Dependency 边**：成功 trial 中，若 \(u\) 先于 \(v\) 使用，且 \(u\) 输出与 \(v\) 输入的 schema overlap 超过阈值 \(\zeta=0.6\)，则加依赖边 \(u\to v\)。
    - **Avoid 边**：若技能对在失败 trial 中共现至少 \(\theta_{avoid}=2\) 次且从未在成功 trial 中共现，则加零权 avoid 边。零权边不参与扩散，只在 bundle 组合时用于排除共载有害技能。实验中该边几乎未被触发。
    - **修剪**：若某技能被检索至少 \(\theta_{obs}=2\) 次却从未被使用，则其所有入向语义边权重乘以 0.5，低于 floor 则删除。

  - **边权演化（改权重 \(w\)）**：
    - 对成功 trial 中实际使用的技能 \(v\)，强化所有指向 \(v\) 的边：  
      \(w^{(t+1)}(u\to v)=w^{(t)}(u\to v)+\eta r_t I[v\in U_t]\)，其中 \(\eta=0.1\)，失败 trial 不贡献正 credit。
    - 边权反映“该关系在历史执行中有多常被证明有用”。

  - **描述演化（改节点文本 \(\phi\)）**：
    - 针对“被使用但排名低于 \(n_{rank}=3\)”且 trial 未达成功阈值 \(r_{succ}=0.9\) 的技能。
    - 借鉴 ProTeGi 的文本梯度下降，做单轮、技能局部优化：
      1. LLM critic 生成自然语言梯度 \(g_q\)，指出描述为何无法匹配查询。
      2. LLM editor 反向修改描述，最多增加约 50 token。
      3. 生成 \(p=2\) 个 paraphrase 变体。
      4. 离线评估器 \(E(q,s;d)\) 重新运行检索，选择使技能进入 top-\(n_{rank}\) 的最佳描述：  
         \(d_s^\star=\arg\max_{d\in Cands(s)}\sum_{q\in Q_s}E(q,s;d)\)。
    - 默认开启 no-eviction

- 默认开启 **no-eviction**：描述更新只做增量改写与变体选择，不删除原技能描述中的既有信息，避免单轮文本梯度造成语义漂移或信息丢失。

### 2.3 更新流程与约束

- **执行与更新解耦**：每条 trial 先完成“检索 → 使用 → 评估成功度 \(r_t\)”，再统一回写三类更新；更新不参与当前 trial 的推理，避免在线污染。
- **成功度门控**：拓扑与边权更新只采信 \(r_t\) 超过成功阈值的 trial；失败 trial 仅用于统计 avoid 共现，不贡献正 credit。
- **图演化与检索算法的接口**：SE-GoS 只暴露 \(E\)、\(w\)、\(\phi\) 三类可变状态，PPR、种子打分、hydration 逻辑完全冻结，因此任何对 GoS 的检索实现都可直接复用。
- **可审计性与可逆性**：所有边与描述变更均可追溯至具体 trial 与触发条件，支持按时间回滚，适合作为多智能体共享的检索基础设施。

## 3. 实验设计与主要结果

### 3.1 实验设置

- **基准与任务**：在技能密集型 agent 基准上评估，任务需要从技能库中召回并组合多个相互依赖的技能才能完成。
- **对比方法**：全量加载技能库、纯向量/词法检索、静态 GoS（含 reverse-aware PPR）、SkillDAG 等依赖感知检索基线。
- **评价维度**：
  - 任务成功率（task success）；
  - 检索质量（必要技能的召回率 / 关键技能是否进入 top-k）；
  - token 成本（hydration 后的上下文长度）；
  - 经验积累效应（随 trial 数增加的性能曲线）。

### 3.2 主要发现

- **成功率提升**：SE-GoS 在相同检索预算下优于静态 GoS 与向量检索基线，说明执行反馈确实补足了静态图缺失的 workflow / dependency 结构。
- **token 效率**：相比全量加载，SE-GoS 以显著更短的上下文达到相当或更高的成功率，验证了“检索足够且必要的技能子集”这一主张。
- **经验可积累**：性能随 trial 数呈现上升趋势并逐步收敛，表明轨迹蒸馏出的边与权重可泛化到后续未见任务，而非仅记忆已见任务。
- **冷启动可行**：semantic-only 确定性构图在没有 LLM 关系验证器与 embedding 服务的条件下即可启动，随后由执行反馈接管结构补全。

### 3.3 消融分析

- **三类更新各自贡献**：拓扑演化（wf / dep 边）对依赖型任务收益最大；边权演化提供稳定但较小的增量；描述演化主要改善“被使用但排名靠后”的长尾技能召回。
- **avoid 边作用有限**：实验中该边几乎未被触发，说明失败共现信号稀疏，零权排除机制更多是安全冗余而非主要收益来源。
- **no-eviction 的必要性**：关闭后描述质量波动更大，验证了增量改写对稳定性的保护作用。
- **种子策略敏感性**：论文设 \(\xi=0\) 使用纯词法种子，表明在确定性冷启动假设下词法信号已足够，语义种子并非必需。

## 4. 贡献与意义

- **概念贡献**：提出“把经验存放在检索 harness / 技能图中，而非模型参数或技能文本中”的范式，强调低成本、可审计、可逆、可共享。
- **方法贡献**：给出免训练、不改检索算法的技能图演化框架，明确三类互补更新（拓扑、边权、描述）与成功度门控机制。
- **工程贡献**：冷启动无需 LLM 验证器与 embedding 服务，降低部署门槛；更新接口与检索实现解耦，便于在现有 GoS 系统上增量落地。
- **实证贡献**：验证执行轨迹可蒸馏为可泛化检索结构，并量化拓扑、权重、描述三类信号的相对价值。

## 5. 局限与批判性评价

- **信号依赖成功标注**：框架高度依赖 trial 成功度 \(r_t\) 的可靠性，若评估器噪声大，边权与拓扑更新可能被误导。
- **schema overlap 假设**：dependency 边依赖输入/输出 schema overlap 阈值 \(\zeta\)，对非结构化或隐式接口的任务适用性存疑。
- **avoid 边信号稀疏**：失败共现统计在实验规模下难以触发，其实际防护价值未被充分证明。
- **描述演化成本**：虽为单轮、局部优化，但仍需 LLM critic/editor 与离线评估器重跑检索，随技能库扩大可能带来可观开销。
- **泛化边界未充分刻画**：论文主张可泛化到未见任务，但缺少对任务分布偏移、技能库新增/淘汰场景的系统压力测试。
- **静态 vs 动态权衡**：将结构判断完全交给执行反馈，可能在早期 trial 不足时退化到接近 semantic-only 图，冷启动初期性能依赖构图质量。

## 6. 总体结论

SE-GoS 的核心主张是：技能检索的瓶颈不在于“是否使用技能”，而在于“如何检索到足够且必要的技能子集”，而解决这一瓶颈的关键资源是执行轨迹中的免费信号。通过把“检索—使用—成功”模式蒸馏为技能图的拓扑、边权与描述，SE-GoS 让静态技能图演化为可积累经验的检索基础设施，且不训练模型、不修改检索算法、不编辑技能内容。实验表明该路径在成功率与 token 效率上均优于静态与纯语义基线，为多智能体共享的技能检索层提供了可审计、可逆、低成本的演化方案。
