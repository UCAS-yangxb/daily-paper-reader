## 摘要
自我演化方法通过允许使用工具的智能体生成自身训练数据，减少了对人工标注轨迹的需求。然而，现有方法通常将轨迹生成与评估分离，依赖静态验证器，无法适应新出现的失败模式；或依赖自一致性信号，可能强化轨迹间共有的错误。联合适应规划、执行与评估提供了一种有前景的替代方案，但引入了根本性的协调挑战：每个组件都会持续改变用于训练其他组件的数据或反馈。我们用 UnifiedPlayers 应对这一挑战，这是一个协作框架，包含生成任务的规划玩家、产生带 Python 工具调用的多轮轨迹的执行玩家，以及构建可执行验证器的评估玩家。我们设计了角色特定的奖励，在 GRPO 下协调三个玩家朝向共享学习目标。在两个模型骨干和十二个推理基准上，UnifiedPlayers 在数学推理上至少比最强先前基线高 3.5%，在通用推理任务上高 3.9%。此外，学习到的验证器达到 84.2% 的对抗检测准确率，而其奖励信号相比自一致性基线具有 2.03 倍的每题方差，从而提供更具判别力的验证。这些结果凸显了专用玩家之间的合作是迈向自增强工具集成智能体的一条有前景路径。

## Abstract
Self-evolving methods reduce the need for human-annotated trajectories by allowing tool-using agents to generate their own training data. Yet existing methods typically separate trajectory generation from evaluation, relying on static verifiers that cannot adapt to emerging failure modes or self-consistency signals that may reinforce errors shared across trajectories. Jointly adapting planning, execution, and evaluation offers a promising alternative, but introduces a fundamental coordination challenge: each component continuously changes the data or feedback used to train the others. We address this challenge with \textbf{UnifiedPlayers}, a cooperative framework comprising a Planning Player that generates tasks, an Execution Player that produces multi-turn trajectories with Python tool calls, and an Evaluation Player that constructs executable verifiers. We design role-specific rewards that coordinate the three players toward a shared learning objective under GRPO. Across two model backbones and twelve reasoning benchmarks, UnifiedPlayers outperforms the strongest prior baseline by at least 3.5\% on mathematical reasoning and 3.9\% on general reasoning tasks. Moreover, the learned verifier achieves 84.2\% adversarial detection accuracy, while its reward signal exhibits 2.03$\times$ higher per-question variance than a self-consistency baseline, providing more discriminative verifications. These results highlight cooperation among specialized players as a promising path toward self-enhanced tool-integrated agents.

## 一、核心问题与研究背景

- **训练数据瓶颈**：训练工具智能体需要大量包含工具调用、观测、错误恢复与最终决策的执行轨迹，但现有语料（Self-Instruct、UltraChat 等）聚焦指令跟随与对话，而非可执行工具交互，人工构建评测数据成本极高（如 Humanity's Last Exam）。
- **自演化方法的局限**：现有自生成数据方法（TaskCraft、AReaL-SEA、Agent0 等）通常把轨迹生成与评估分离：
  - 依赖**静态验证器**，无法适应新出现的失败模式；
  - 依赖**自一致性 / 多数投票伪标签**，只验证"一致性"而非"正确性"，轨迹间共有的错误会被强化，产生错误标签与误导性的优势更新。
- **核心挑战——循环依赖（cyclic interdependence）**：一旦规划、执行、评估三者联合自适应，每个组件都在持续改变另外两者的训练数据或反馈：
  - 规划改变任务分布；
  - 执行改变轨迹与失败模式；
  - 评估改变引导两者的奖励。
  - 缺乏协调时会诱发**退化学习循环**：规划偏向简单/重复/不可验证任务；执行强化被评估者错误接受的自信错误轨迹；评估坍缩为"全接受""全拒绝"或重复模板，内部奖励升高但真实能力不涨。
- **论文含义**：提出 UnifiedPlayers，把规划、执行、评估统一为三个通过**共享可执行证据**协作的玩家，探索"专业化玩家合作"作为工具集成智能体自我增强的路径。

## 二、方法论

### 1. 核心思想
- 三个可训练策略：**Planning Player（Task-Setter，出题）**、**Execution Player（Solver，解题）**、**Evaluation Player（Critic-Coder，写可执行验证器）**。
- 三者不共享标量奖励或参数，而是通过**共享的可执行证据（判决矩阵）**耦合，各自从同一证据的不同摘要中导出**角色特定奖励**。
- 采用**交替 GRPO**：每次只更新一个玩家，另外两个固定，以缓解循环依赖带来的非平稳性。

### 2. 关键技术细节与流程
- **交互流程**：Planning 生成任务 q → Execution 采样 K 条带 Python 工具调用的多轮轨迹 → Evaluation 生成 M 个可执行 Python 验证器 → 固定扰动引擎为每条轨迹生成 P 个对抗变体 → Python 沙箱对原始与扰动轨迹执行所有可解析、可编译的验证器。
- **判决矩阵**：对有效验证器集合 I_valid(q)（数量 M_q），记录 Z_orig[i,k] = v_i(τ_k)、Z_adv[i,k,j] = v_i(τ_k,j^adv)，拼接为
  Z(q) = [Z_orig | Z_adv] ∈ {0,1}^{M_q × K(1+P)}
  - 列反映 Execution 输出质量，行反映 Evaluation 输出质量，整体摘要反馈给 Planning。
- **交互记录**：ξ(q) = (q, T(q), V(q), T^adv(q), Z(q), ρ^red(q))，其中 ρ^red 为验证器源码冗余度。
- **角色特定奖励**：
  - **Planning**：r_T(q) = w_unc·U(q) + w_ver·V(q) − w_rep·R(q)
    - U(q) = min(p̂, 1−p̂)，p̂ 为 K 条轨迹中多数答案占比（不确定性/接近执行能力边界）；
    - V(q) = m(q)·(1/M_q)Σ_{i∈I_valid} ρ_i^adv（可写性，含有效验证器比例，无有效验证器或无一拒绝扰动时为 0）；
    - R(q) 为问题重复惩罚。
  - **Execution**：r_S(τ_k) = (1/M_q)Σ_{i∈I_valid} v_i(τ_k)，即取 Z_orig 对应列均值。用**实际执行的检查**替代多数投票伪标签。
  - **Evaluation**：r_C(v_i) = α·ρ_i^gold + β·ρ_i^adv − γ·ρ_i^red
    - ρ^gold 为原始轨迹接受率，ρ^adv 为对抗变体拒绝率，ρ^red 为与其他有效验证器的最大源码相似度；
    - 全接受者无对抗奖励，全拒绝者无原始通过奖励，重复模板受冗余惩罚。
    - 默认权重 α=0.4, β=0.5, γ=0.1；Planning 权重 w_unc=1.0, w_ver=1.0, w_rep=0.5（BLEU 重复项）。
- **扰动引擎（固定、非学习）**：5 条规则独立施加，每条轨迹生成 5 个变体：
  - 局部编辑：arg mutation（数值参数小扰动）、step drop（删一个推理步）、step swap（交换相邻步，代码与其输出绑定为整体）；
  - 全局编辑：early terminate（截断并注入错误答案）、tool substitute（改工具类型保留代码体与输出）。
- **优化**：每玩家用 GRPO，组内归一化优势 bA_{p,g} = (r_{p,g} − r̄_p)/(s_p + ε)；token 级裁剪比率与 KL 惩罚（对迭代开始时的参考检查点）：
  ℓ = min(ϱ·bA, ϱ̄·bA) − β_p·D_KL。
  迭代级目标 J_UP = (1/3)Σ_p J_p 仅为报告用汇总，三个目标在各块内独立优化，**不混合奖励或跨玩家平均梯度**，梯度也不穿过其他玩家或数据生成过程（固定记录 + stop-gradient）。
- **更新顺序**：每轮外层迭代依次为 Planning → Execution → Evaluation 的多个优化步（非单次更新）；后序块使用同轮内已更新的前序玩家检查点（fresh feedback）。
- **理论分析**：块内奖励目标因记录固定而局部平稳；由 Pinsker 不等式，若输出分布平均 KL ≤ δ_p，则 TV 距离 ≤ √(δ_p/2)——但这是条件性结论，不保证单调改进或收敛。

## 三、实验设计

### 1. 模型与框架
- 两个开源骨干：**Qwen3-4B-Base**、**MiMo-7B-Base**，三个玩家均从同一骨干初始化。
- 基于 **VeRL** 实现，工具沙箱为 **VeRL-Tool**（子进程隔离、无网络、仅标准库、单次调用 10 秒超时、512 MB 内存上限）。
- 每任务采样 K=8 条执行轨迹，M=4 个验证器，P=5 个扰动变体，共 K·M·(1+P)=192 次沙箱执行。

### 2. Benchmark（12 个）
- **数学（7 个）**：AMC、MATH-500、GSM8K、Minerva、Olympiad-Bench、AIME24、AIME25（AMC/AIME 用 mean@32，其余 pass@1）。
- **通用/代码（5 个）**：SuperGPQA、MMLU-Pro、BBEH、GPQA-D、HumanEval。

### 3. 对比方法（6 个基线）
- Vanilla（无工具、无训练）、Tool-augmented（有 Python 工具但无 RL）；
- 三个自演化框架：Absolute Zero、R-Zero、Socratic-Zero；
- 最接近的前作 **Agent0**（Curriculum + Executor 双玩家 GRPO，自一致性 + 工具调用频率奖励、多数投票伪标签）。
- 所有基线均由作者在统一评测协议（相同 prompt、解码设置、benchmark 划分、工具沙箱）下**重新实现**。

### 4. 消融与机制分析
- **2×2 因子设计**：Execution 始终训练，Planning 与 Evaluation 分别冻结/可训练，3 个配对随机种子。
- **Fresh vs. stale feedback**：同算力匹配（432 GPU-hours/seed），延迟一轮使用更新检查点作为对照。
- **组件消融**：去扰动引擎、单验证器（M=1）、Planning 奖励去 V(q)、去多样性惩罚、仅单次迭代。
- **扩展分析**：扰动规则子集（局部 vs 全局）、验证器池大小 M∈{1,2,4,8}、Evaluation 奖励系数扫描。
- **过程/机制指标**：规划不确定性 U(q)、执行准确率、对抗拒绝率随迭代变化；每题奖励方差对比；验证器判别准确率；优化稳定性诊断（梯度范数及 CV、KL、裁剪率、熵保持、负步率、最大精度下降）。

## 六、主要结论与发现

- **主结果**：UnifiedPlayers 在两个骨干上均取得最佳平均成绩：
  - 数学：Qwen3-4B-Base 56.4、MiMo-7B-Base 64.6，比最强基线 Agent0 高 3.7 / 3.6；比 Tool-augmented 参考高 12.4。
  - 通用：46.1 / 41.2，比 Agent0 高 4.0 / 3.9；BBEH 提升尤为明显（此前基线均低于 12）。
- **训练分布外迁移**：Planning 只生成数学任务，但通用领域基准一致提升。
- **验证器质量**：学习到的验证器对原始/扰动轨迹的判别准确率 **84.2%**，接近 GPT-4o 的 90.8%，且训练期间无需外部 API。
- **奖励判别力**：每题奖励方差为 Agent0 式离线自一致性的 **2.03×**（0.030 vs 0.015）。
- **协同动态**：三轮迭代中执行准确率 52.5%→63.3%、评估对抗拒绝率 31%→79%、规划不确定性 0.18→0.39（任务变难）。
