## 摘要
金融问答系统通常通过更好的检索、提示或智能体协调在部署前进行改进，此后其可靠性行为便固定不变。在实践中，新的 SEC 申报文件问题会反复暴露出在期间、实体、证据使用和计算方面的异质性错误。现有自我改进方法能将失败转化为新行为，但对修正应作用于何处、或可能破坏哪些原本正确的答案，提供的控制有限。因此，我们将部署后的改进界定为受控的行为维护：反复出现的失败应转化为有作用域的技能补丁，且每个补丁都应在不引入回归的前提下赢得部署资格。我们在 FINSKILLOPS 中实例化了这一观点，这是一个用于 SEC 申报文件问答的多智能体系统。FINSKILLOPS 从基于证据的、分类型的失败诊断中提炼可复用技能，并通过定向验证、受保护案例的回归检查、阴性对照以及版本化替换或退役来治理这些技能。在六个金融问答基准上，一个单一冻结的技能注册表在所评估系统中取得了最高的判定加权正确率和参考一致性。在增强基准上，演化后的技能将正确率从 3.70 提升至 4.55。在一项独立的 12 轮运行研究中，33 个提议技能中仅有 6 个被提升，同时监测非正确率从 20.0% 降至 12.5%。这些结果确立了受控的技能作用域、准入和生命周期管理是可靠自我改进的基础。

## Abstract
Financial QA systems are typically improved before deployment through better retrieval, prompting, or agent coordination, leaving their reliability behavior fixed thereafter. In practice, new SEC-filing questions repeatedly expose heterogeneous errors in period, entity, evidence use, and calculation. Existing self-improvement methods can turn failures into new behaviors, but offer limited control over where a correction should apply or which previously correct answers it may break. We therefore frame post-deployment improvement as controlled behavioral maintenance: recurring failures should become scoped skill patches, and each patch should earn deployment with- out introducing regressions. We instantiate this view in FINSKILLOPS, a multi-agent system for SEC filing QA. FINSKILLOPS derives reusable skills from evidence-grounded, typed failure diagnoses and governs them through targeted validation, protected-case regression checks, negative controls, and versioned replacement or retirement. Across six financial QA benchmarks, a single frozen skill registry achieves the highest verdict-weighted correctness and reference consistency among the evaluated systems. Evolved skills raise correctness from 3.70 to 4.55 on our enhanced benchmark. In a separate 12-round operational study, only six of 33 proposed skills are promoted, while the monitoring non-correct rate falls from 20.0% to 12.5%. These results establish controlled skill scope, admission, and lifecycle management as the foundation for reliable self-improvement.

# FINSKILLOPS 论文总结

## 1. 核心问题与整体含义

- **研究动机**：金融问答系统（尤其是面向 SEC 申报文件的 QA）通常在部署前通过更好的检索、提示工程或多智能体协调来优化，一旦部署，其可靠性行为便固定不变。
- **现实痛点**：部署后新出现的 SEC 文件问题会反复暴露异质性错误，集中在四个方面：
  - **期间错误**（period mismatch，如混淆 FY2025 与 FY2026）
  - **实体错误**（entity confusion，跨公司/跨申报文件混淆）
  - **证据使用错误**（unsupported claim，无支撑或证据冲突）
  - **计算错误**（calculation error，如份额与所引金额不一致）
- **现有方法局限**：自演化智能体（如 Reflexion、Voyager、AutoSkill、SkillOpt）虽能把失败转化为新行为，但**难以控制修正的作用范围**，也无法预判新行为是否会**破坏原本正确的答案**（回归风险）。
- **论文主张**：将部署后改进重新界定为**受控的行为维护（controlled behavioral maintenance）**——反复失败应转化为**有明确作用域的技能补丁（scoped skill patches）**，且每个补丁必须通过验证才能"赢得部署资格"，且不引入回归。

## 2. 方法论

### 2.1 核心思想

FINSKILLOPS 将系统拆分为两部分：
- **固定的服务基底（substrate）**：多智能体 SEC 文件 QA 管线
- **可演化的技能注册表（Skill Registry）**：存放自然语言可靠性指令，带适用条件、防误触发护栏、版本与状态

系统仅在**两个注入点**用技能文本影响回答：**查询分解**与**最终综合**，底层模型与检索组件保持不变。

### 2.2 服务管线（Serving Pipeline）

- **多模态解析**：用 MinerU 将申报文件解析为文本块、表格、图形，并保留章节路径、报告期、申报实体等元数据。
- **五类分析师智能体**：general（总是激活）、quantitative、market、legal、company，由编排器按问题类型选择性激活。
- **多路径检索**：稀疏（BM25）+ 稠密（bge-m3 + Chroma）+ 摘要索引三条路径，经重排序后供各智能体生成草稿。
- **答案综合**：编排器融合各智能体草稿与证据，生成最终答案。

### 2.3 失败驱动的技能演化（Algorithm 1）

**两阶段失败诊断**：
1. 第一阶段：读入问题、失败答案、评判反馈、检索上下文，提出失败假设并制定检索计划。
2. 确定性 grep 执行该计划，检索申报文件原文。
3. 第二阶段：读入检索片段，输出根因类型、支撑证据、失败解释及 **propose / park / do-not-fix** 建议。

失败按模式聚类，频率超过阈值 τ 的模式进入技能提议阶段。

**技能提议**：
- LLM 从代表性失败及其证据起草技能，包含**适用条件、行为、排除情况、注入位置**。
- 可修订已有技能而非新增，以保持注册表精简、避免冲突。
- 技能是自然语言指令，**不生成可执行代码**。

**运行时应用**：
- 路由器根据查询、语料元数据、证据特征，从冻结注册表中选择激活技能。
- 参考金标答案、关键点标签、评判反馈**不作为服务输入**。

### 2.4 门控晋升与生命周期（关键公式）

候选技能 $s'$ 的晋升需同时满足三个条件（公式 1）：

$$\text{Acc}_{V_m}(S') > \text{Acc}_{V_m}(\hat{S}) \quad \wedge \quad \text{Reg}_P(S', \hat{S}) = 0 \quad \wedge \quad \text{FalseTrig}(s') = 0$$

其中：
- **Acc_{V_m}**：在模式 m 的定向验证子集上的正确率
- **Reg_P**：在保护套件 P（此前正确 + 高风险案例）上从 Correct 变为非 Correct 的回归计数，必须为 0
- **FalseTrig**：在阴性对照（no-op、多期、跨公司查询）上的误触发次数，必须为 0

**生命周期管理**：
- 晋升的技能获得版本号
- 修订版本取代旧版本（旧版变 inactive）
- 行为被吸收且不再激活的技能，通过移除测试后退役
- 注册表保留所有版本的历史（起源失败、验证结果、保护套件结果）

## 6. 主要结论与发现

- **性能领先**：单一冻结技能注册表在 6 个基准上均取得最高 W-Corr. 和 Ref. Cons.；增强内部基准 W-Corr. 从 3.70 提升至 **4.55**。
- **门控有效**：12 轮运营中 **33 个候选仅 6 个晋升**（5 个明确因保护集检查失败，共 7 次条目级回归事件），部署注册表全程**零保护回归**。
- **监控错误率下降**：演化集非正确率从 30.0% → 18.3%，监控集从 20.0% → **12.5%**。
- **注册表通过整合而非累积演化**：R5–R12 保持 4 个活跃技能，静态技能文本从 421 token 缩减至 347 token。
- **消融结论**：
  - 移除 **Skill Evolution** 造成最大 W-Corr. 下降（内部基准 −0.85）
  - 移除 **Protected Gate** 虽提升定向验证增益（+0.78 vs +0.62），但**引入 3 次保护集回归**
  - 移除 **Failure Taxonomy** 下降 −0.47
  - 单技能中 **period alignment v2** 贡献最大（移除后 Δ = +0.34）
- **适配方法对比**：AutoSkill 平均 W-Corr. 2.00（−1.22 vs init），SkillOpt 2.66（−0.56），FINSKILLOPS 3.66（+0.44，4/4 胜出）。
- **跨注册表泛化**：内部演化注册表在 FinanceBench/SECQUE 监控子集上仍优于本地演化注册表。

## 7. 优点

- **问题重构有洞见**：将"部署后自改进"从"性能提升"重新框定为"受控行为维护"，强调**作用域、准入、回归**三要素，直击自演化系统的核心风险。
- **门控机制严谨**：定向验证 + 保护套件零回归 + 阴性对照三条件缺一不可，且所有拒绝/延迟/撤回都被记录。
- **失败诊断证据化**：两阶段诊断 + 确定性 grep 回溯申报原文，能区分"选错期间"与"操作数正确但算错"这类表面相似、根因不同的错误。
- **生命周期管理完整**：支持版本化替换、吸收合并、移除测试退役，注册表可增长也可收缩。
- **实验设计细致**：提供 BCa bootstrap 配对置信区间、技能激活/移除对照、冲突事件记录、跨注册表评估。
- **成本透明**：报告了 token 消耗与首 token 时延，并诚实说明技能文本的边际成本未被单独测量。

## 8. 不足与局限

- **覆盖范围有限**：证据仅覆盖 SEC 申报文件 QA；适配对比**未在匹配演化预算下进行**，其他金融工作流仍是未来工作。
- **因果归因不足**：12 轮研究同时改变了路由与诊断，监控集每轮被评估，**测的是部署改进而非技能文本的孤立效应**，**未建立盲泛化**。
- **可验证性受限**：候选工件、准入日志、划分清单不完整，难以验证门控决策及演化输入与基准/消融问题之间的条目级隔离。
- **保守门控代价高**：27/33 候选被拒绝、延迟或撤回；准入需在定向、保护、阴性对照三集上跑评估，**拖慢适应速度**。
- **人工评审缺失**：金融专家审查路径**未配备人员**，准入决策完全依赖自动检查；评判一致性研究使用**作者组标注者**，非独立领域专家。
- **资源信息缺失**：**未报告 GPU 型号、数量、训练时长**等算力细节。
- **定性案例的局限**：案例仅通过摘要答案和技能行为说明特定修复与未解决错误，代表性有限。
- **潜在偏差风险**：评判使用单一 LLM（Qwen3-Max），虽提供了 GPT-5.5 的一致性检查，但**并非等价性检验**；自动评判无法独立验证所有主张与检索证据的支撑关系。
