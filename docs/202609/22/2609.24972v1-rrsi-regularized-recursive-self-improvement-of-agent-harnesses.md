## 摘要
LLM 智能体的能力在很大程度上由其智能体框架所放大，即围绕冻结骨干模型的提示、控制流、工具、记忆与上下文管理。近期方法通过迭代地提出并选择智能体框架的组件级编辑，日益自动化这一过程，实际上在智能体系统层面建立了一种递归自我改进（RSI）。然而，这种递归演化可能通过记忆训练任务而过拟合，表现出较大的分布内增益，而这些增益在分布外基准上会缩小甚至消失。我们提出智能体框架的正则化递归自我改进（RRSI），其通过约束演化候选的提出与选择，将正则化原则引入框架自我改进。提议器采用随时间退火的预算运行，限制一个候选可以捆绑的编辑数量，并基于演化历史鼓励探索未探索的轨迹。选择器配备了一个评论器（critic）和一个修剪器（pruner）：评论器筛选特定于基准的提议，而修剪器则移除过小、代价过高或不再有用的更改。这些约束共同倾向于可复用的智能体机制，而非特定于基准的机制，甚至噪声。在涵盖编码、智能体工作空间和工程设计任务的八个基准上，RRSI 在其演化所针对的划分上最高提升 14.1 分，在五个分布外基准上最高提升 4.7 分，同时生成的框架运行所需的策略 token 比未正则化演化少 30%。代码见 https://github.com/google-research/rrsi，项目主页见 https://regularized-rsi.com/。

## Abstract
An LLM agent's capability is largely magnified by its harness, namely the prompts, control flow, tooling, memory, and context management surrounding the frozen backbone model. Recent methods increasingly automate this process by iteratively proposing and selecting component-wise edits of an agent harness, practically establishing a form of recursive self-improvement (RSI) at the agent-system level. However, such recursive evolution may overfit by memorizing the training tasks, showing large in-distribution gains that shrink or even vanish on out-of-distribution benchmarks. We introduce Regularized Recursive Self-Improvement of Agent Harnesses (RRSI), which incorporates the principles of regularizations into harness self-improvement by constraining the evolution candidate proposal and selection. The proposer operates with a temporally annealed budget, limiting how many edits a candidate can bundle, and it encourages unexplored trajectories based on evolution history. The selector is equipped with a critic and a pruner: the critic screens benchmark-specific proposals, while the pruner, removes changes that are too small, too expensive, or no longer useful. Together these constraints favor reusable agent mechanisms over benchmark-specific ones or even noises. Across eight benchmarks spanning coding, agentic workspace and engineering design tasks, RRSI gains up to 14.1 points on the split it evolves against and up to 4.7 points on the five out-of-distribution benchmarks, while producing a harness that runs on 30% fewer policy tokens than the unregularized evolution. Code is available at https://github.com/google-research/rrsi and project page is https://regularized-rsi.com/.

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体的能力不仅取决于冻结的骨干模型，还高度依赖其 **harness（智能体框架）**，包括提示词、控制流、工具接口、记忆、技能文件与上下文管理。近期研究倾向用 LLM 自动迭代地提出并选择 harness 的组件级编辑，从而在智能体系统层面形成一种 **递归自我改进（RSI）**。
- **核心问题**：这种递归演化反复使用有限的 evolve set 进行候选提议与选择，构成 **自适应过拟合**。表现为：
  - evolve set 分数明显提升；
  - 但在分布内 held-out 或分布外（OOD）基准上，增益缩小甚至消失；
  - 甚至部分方法最终低于初始 harness \(H_0\)。
- **问题成因**：论文将其归结为三种耦合行为：
  - **benchmark-specific fitting**：编码基准特定模式、任务名、实体名或答案逻辑；
  - **noise chasing**：将评估噪声带来的随机高分误认为真实改进；
  - **complexity accumulation**：累积复杂度、上下文与推理成本，却未提升可复用的智能体机制。
- **整体含义**：论文主张，agent-system 层面的 RSI 不仅要控制“能改什么”，还要正则化“如何把反复反馈转化为持久状态”。RRSI 的目标是在保持 harness 编辑空间开放的同时，让搜索轨迹偏向可迁移、可复用、低冗余的机制。

## 2. 方法论：RRSI 的核心思想与关键技术

### 2.1 核心思想

- 不限制 harness 的可编辑空间 \(\Omega(H)\)，而是 **正则化搜索轨迹**。
- 将经典正则化思想类比到 harness 演化：
  - **\(L_0\) 风格**：限制单轮候选可捆绑的独立编辑数量；
  - **Lasso / \(L_1\) 风格**：结构剪枝，删除长期无正向贡献的组件；
  - **Ridge / \(L_2\) 风格**：复杂度感知接受，抑制未付费的资源膨胀。
- 整体流程：每轮在 evolve set 上运行当前 harness，生成反馈，提议器生成候选，critic 预筛，评估候选，选择器在非补偿条件下接受最优候选，否则保留 incumbent。

### 2.2 提议侧正则化

- **\(L_0\) 风格退火更新稀疏性**
  - 每轮限制候选可包含的独立可归因编辑数：
    \[
    b_t=\left\lceil b_{\min}+(b_{\max}-b_{\min})\cdot \frac12(1+\cos(\pi t/T))\right\rceil
    \]
  - 早期允许较宽的协调编辑，后期逐渐稀疏，便于归因。
  - 对编辑池 \(E_t\) 的子集指示向量 \(z_t\)，约束 \(\|z_t\|_0\le b_t\)。

- **证据感知的信用分配**
  - 记录每个候选的组件、假设、源码 diff、分数变化、成本变化及是否被接受。
  - 被拒绝的机制作为负证据保留，成功机制保留显式信用。
  - 随着编辑预算退火，后续轮次更容易识别单个改动是否真正有效。

- **结构化探索**
  - 当最近 \(w\) 轮进展未超过噪声带 \(\delta\) 时，视为搜索停滞。
  - 保留少量提议预算给尚未被测量的组件类型，类似多样性或熵正则化。
  - 组件词表包括：prompt、control_flow、config、output_plumbing、context_mgmt、client_tool、skill、memory、subagent。

### 2.3 选择侧正则化

- **泄漏筛查（Leakage Screening）**
  - 在完整评估前，由 critic 阅读候选 diff，拒绝显式编码任务名、实体名、任务特定值、答案或基准特定逻辑的编辑。
  - 也拒绝无意义的惰性机制。

- **噪声调整的性能底线**
  - 预先重复评估未变化的 base harness，估计噪声带 \(\delta\)。
  - 候选必须满足：
    \[
    \hat S(H')\ge S^\star-\delta
    \]
  - 防止搜索通过一连串微小回退“走下坡路”。

- **Ridge / \(L_2\) 风格复杂度感知接受**
  - 若增益超过噪声带 \(\Delta S>\delta\)，要求：
    \[
    \Delta C\le \beta_0+\beta_1\Delta S
    \]
  - 其中 \(\Delta C\) 为相对策略 token 成本变化；额外推理成本必须由可测性能提升来证明。
  - 若增益在噪声带内，则使用整形规则：
    \[
    w_s\Delta S-w_c\Delta C+w_n\nu_t(H')>0
    \]
    其中 \(\nu_t(H')\) 统计此前从未进入获胜编辑的结构组件类型数量。

- **Lasso / \(L_1\) 风格结构剪枝**
  - 跟踪最近窗口内被编辑过的组件是否产生严格正增益。
  - 对 \(g_t(\ell)\le 0\) 的组件，作为删除目标反馈给后续提议器。
  - 使保留的 harness 结构更稀疏，而非仅整体成本更低。

- **领域特定非补偿守卫**
  - 编码与 agentic workspace 实例无额外守卫。
  - 工程设计实例额外拒绝有效输出率下降超过 0.03 或未提交率上升超过 0.02 的候选。

### 2.4 算法流程简述

1. 在 evolve set 上执行当前 harness \(H_t\)，收集轨迹与反馈 \(F_t\)。
2. 根据轮次计算退火编辑预算 \(b_t\)。
3. 根据历史判断是否停滞，生成探索指令与剪枝目标。
4. 提议器生成正则化候选集合 \(H_t\)。
5. 对候选进行泄漏筛查。
6. 并行评估候选，计算 \(\Delta S\)、\(\Delta C\)、结构新颖性。
7. 仅接受满足噪声底线、复杂度规则和领域守卫的候选。
8. 在可接受候选中选最高分者作为 \(H_{t+1}\)，否则保留 \(H_t\)。
9. 更新历史、最佳分数与剪枝统计。
