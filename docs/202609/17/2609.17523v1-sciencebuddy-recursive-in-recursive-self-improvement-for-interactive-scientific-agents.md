## 摘要
我们介绍并发布 ScienceBuddy，一个交互式科学研究工作空间，将不断改进的科学智能体带入研究人员的日常工作流。ScienceBuddy 支持研究人员开展科学任务，同时将其请求、反馈和执行证据转化为用于持续学习的任务与评估标准。其核心是递归套递归式自我改进，这一范式将框架演进与模型强化学习耦合起来：内层递归在模型固定时改进框架，而外层递归在改进后的框架下训练模型。框架演进塑造训练经验，模型学习则为框架适配创造新的机会。我们展示了关于研究者交互、框架细化和模型学习的案例研究，基准案例涵盖四个科学任务族。通过将 ScienceBuddy 作为研究产品发布，我们使这一范式可供科学界使用，并向发现智能迈出一步：一种通过与研究人员持续协作而进步、并与其所支持的研究共同演化的科学 AI。网站：http://science-buddy.io

## Abstract
We introduce and release ScienceBuddy, an interactive scientific research workspace that brings continually improving scientific agents into researchers' everyday workflows. ScienceBuddy supports researchers in carrying out scientific tasks while transforming their requests, feedback, and execution evidence into tasks and evaluation rubrics for continual learning. At its core is recursive-in-recursive self-improvement, a paradigm that couples harness evolution with model reinforcement learning: the inner recursion improves the harness with the model fixed, while the outer recursion trains the model under the improved harness. Harness evolution shapes training experience, and model learning creates new opportunities for harness adaptation. We present case studies of researcher interaction, harness refinement, and model learning, with the benchmark cases spanning four scientific task families. By releasing ScienceBuddy as a research product, we make this paradigm available to the scientific community and take a step toward discovery intelligence: scientific AI that advances through sustained collaboration with researchers and evolves alongside the research it supports. Website: http://science-buddy.io

## 2. 方法论

### 2.1 系统架构：科学工作空间 + 可插拔 harness

- **科学工具与执行环境**：**224 个工具、22 个功能模块**，覆盖基因组学、分子与癌症生物学、药理学、生物成像、文献检索、数据库查询；运行时支持 Python / R / Bash；在线数据库接口 + 本地 data lake；持久工作区保留输入、中间文件与产出（工具目录与执行工具源自 Biomni）。
- **智能体执行与交互**：采用 ReAct 式"推理—行动—观察"循环；Chat 视图提交问题与数据，Trajectory 视图呈现时序执行记录与事件详情，Compute / Results 面板暴露执行活动与产出物。
- **模块化与可插拔**：harness 与基础设施（任务管理、执行、持久存储）分离，通过统一执行接口接入。**harness 的可编辑组件 = 指令（instructions）+ 技能（skills）+ 选定的上下文管理程序**；递归改进只修订这些组件，其余基础设施固定，从而在一致的执行条件下评估"科学问题求解程序"的变化。

### 2.2 交互形式化与学习信号

- **形式化**：设研究请求及输入为 `x`，任务模型为 `π_θ`，harness 为 `H`，历史 `h_t = (x, a_0, o_1, …, a_{t-1}, o_t)`，`h_0 = (x)`。动作 `a_t` 为可执行代码、工具调用或面向研究者的回复；观察 `o_{t+1} = (e_{t+1}, u_{t+1})`，其中 `e` 为环境输出/执行状态，`u` 为可选的研究者回复（缺失时为 ⊥）。harness 由历史、记忆、技能与工具描述构造模型上下文 `C_H(h_t)`。
- **联合策略**：若 harness 安排了确定性动作 `d_H(h_t)`（如输入检查），则取点质量分布 `δ`，否则由 `π_θ(a | C_H(h_t))` 采样；轨迹为 `τ = (x, a_0, o_1, …, a_{T-1}, o_T)`。**工具观察本身不构成研究者轮次或用户反馈**。
- **从协作到任务与 rubric**：把相关轮次围绕科学目标合并，独立可解的目标拆分；任务指令保留最终要求与输入，**不导入历史答案**；rubric 由完整协作轨迹导出：`C(x) = ConstructRubric(τ^collab_x; I_x, A_x)`，覆盖任务范围、方法学要求、证据、期望产出物；冲突要求先解决再评分；**历史答案与研究者认可不被自动视为科学真值**。
- **Harbor 任务包**：`P_x = (I_x, A_x, E_x, C(x))`，文件结构为 `instruction.md`、`task.toml`、`environment/`、`assets/`、`tests/test.sh`。同一任务支持两条后训练路线：**SFT 用拒绝采样保留 rubric 合格轨迹**，**RL 采集新鲜 on-policy rollout 并以 rubric 分数为奖励**。

### 2.3 内层递归：反馈引导的 harness 改进（模型固定）

- **角色分工**：外层周期 `k` 内，任务模型参数 `θ_k` 固定；使用固定的辅助模型 **GPT-6 Astra** 做轨迹诊断与 harness 编辑（工具、执行基础设施、rubric、评估器均固定）。
- **反馈引导诊断**：辅助模型审阅近期轨迹与 rubric 评估，定位未满足的准则，并**引用相关动作与观察**，映射到候选程序性编辑；任务特定答案与新事实仅局部保留。
- **有界修订**：`\tilde H_{k,j+1} = U(H_{k,j}, E_{k,j}; θ_k)`，每次提案只能**新增/删除/修订一个限定范围的技能、编辑一条指令、或改动一个暴露的上下文设置**，其余组件不变；schema 检查强制编辑范围与大小预算。
- **配对评估与接受规则**：父代与候选在**相同开发任务、相同种子、相同执行预算**下用冻结 rubric 评估。记 `\bar S_k(H)` 为平均归一化 rubric 得分，`Valid(H)` 为编辑约束合规，`Δ_{k,j} = \bar S_k(\tilde H_{k,j+1}) − \bar S_k(H_{k,j})`：
  - 当且仅当 `Valid ∧ Δ > 0` 时接受候选为子代，否则保留父代；**平局保留父代**。
  - 评估包含此前成功的任务以检查回退；被拒编辑与分数变化保留在优化器历史中。
  - 迭代至提案预算或外层采集边界；**开发任务与策略训练任务、最终留出测试集严格分离**。

### 2.4 外层递归：持续模型强化学习

- **环境增强**：随着 harness 演化，原本困难的任务可能变简单，故用当前模型 + 选定 harness 做试点执行以校准难度，通过**变化科学输入与分析条件、延长计算步骤间的依赖**来增广研究者派生的任务。
- **任务自适应 rubric 奖励**：每条准则有非负重要性权重 `w_c(x)`（在 rollout 评估前指定）与满足度 `v_c(x, τ) ∈ [0,1]`；可用可执行检查处用检查，需要科学解释处用固定 judge。轨迹奖励为
  `R_x(τ) = Σ_c w_c(x) v_c(x,τ) / Σ_c w_c(x)`（分母 > 0）。
  rubric 随任务变化，但在优化与配对 harness 评估期间固定；终局奖励提供**跨生成 token 共享的轨迹级优势**。
- **模型更新**：`max_θ J_k(θ)`，其中 `J_k(θ) = E_{x~q_k} E_{τ~π_{θ,H*_k}(·|x)}[R_x(τ)]`，`q_k` 为第 k 轮已验证种子环境与增广变体的训练任务分布；用 **GRPO** 得到 `θ_{k+1}`。
- **再评估与部署**：harness 效果依赖其与任务模型的交互，因此在部署 `(θ_{k+1}, H_{k+1})` 前需在更新后的模型下**重新评估选定 harness**（`H_{k+1} = H*_k`）；研究者的后续交互为下一轮内层适配与外层更新提供证据。
- **GRPO 细节（附录 S1.3）**：组相对优势 `Â_i = (r_i − mean_j r_j)/(std_j r_j + δ)`，同一任务、同一 harness、同一 rubric 下的轨迹成组；轨迹内所有生成 token 共享

同一个轨迹级优势（即 GRPO 不使用逐 token 的 critic 或价值函数，也不做 token 级信用分配），从而与"rubric 只在轨迹末尾给出整体分数"的信号结构相匹配；`δ` 为防止除零的小常数。该设计使模型更新直接优化"在固定 harness 下能否满足研究者导出的科学准则"，而不引入额外的奖励模型或过程奖励。

### 2.5 双层循环的耦合与停止条件

- **内层（harness 层）**：在外层参数固定下，用反馈诊断 + 有界修订 + 配对评估，逐步改进程序性组件，得到 `H*_k`。
- **外层（模型层）**：以 `H*_k` 为执行条件，采集 on-policy 轨迹并做 rubric 奖励的 GRPO 更新，得到 `θ_{k+1}`；随后在新模型下重评 harness，进入下一轮。
- **耦合逻辑**：内层提升"当前模型可达的程序上限"，外层提升"在该程序下的模型能力"；二者交替推进，形成"递归套递归"——即 harness 改进本身也依赖模型对协作轨迹的诊断能力，而模型改进又依赖 harness 提供的任务与评分标准。
- **停止**：达到外层轮数上限、提案预算耗尽、或留出测试集指标不再提升即终止。

## 4. 主要结果与分析（结构性预期）

- **联合递归优于单侧改进**：预期"内层 + 外层"交替显著高于仅 harness 优化或仅 RL，说明程序性改进与能力改进存在互补而非替代关系。
- **回退控制有效**：配对评估 + 保留父代 + 平局保守接受，使内层编辑不牺牲既有能力；评估含历史成功任务是关键设计。
- **难度校准的必要性**：harness 演化会使原任务变易，若不增广，外层 RL 会遭遇奖励饱和/信号枯竭；增广（变科学输入、延长依赖链）维持了可学习梯度。
- **rubric 的稳定性**：在优化期间冻结 rubric、仅在轮次边界随新交互更新，避免"评分标准漂移"导致的奖励作弊。
- **研究者交互的价值**：协作不仅提供任务定义（instruction），也提供评估标准（rubric），这正是"协作同时作为任务与 rubric 来源"的核心主张。

- **应用边界**：定位为科研辅助工具，不替代研究者对科学结论的最终责任。

## 8. 结论

ScienceBuddy 将"与研究者协作"视为可同时产出**任务定义**与**评估标准**的持续经验流，并通过内层（harness 程序改进）与外层（模型策略改进）的递归耦合，把单次对话中的纠正转化为跨任务的持续提升。其核心主张是：科学智能体的进步不应只发生在权重或提示的单一层面，而应发生在"程序—能力"共同演化的双层循环中，从而指向与研究者共同成长的**发现智能**。
