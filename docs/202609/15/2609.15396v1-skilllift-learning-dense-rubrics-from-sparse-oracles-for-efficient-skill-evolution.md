## 摘要
基于LLM的智能体日益依赖持久化技能，即可复用的过程性提示，以在不更新权重的情况下适应任务。现有技能自演化方法根据执行反馈直接修改技能文本，但每次预言机评估都需要完整的智能体 rollout，造成监督瓶颈，使搜索局限于修复失败的更新。我们的关键洞见是：排序是比绝对结果回归更平滑的监督目标：判断哪个技能更好比预测精确分数需要更少的预言机评估。基于这一洞见，我们提出 SkillLift，它通过学习与预言机对齐的评分标准作为结构化评估空间，将技能搜索与预言机成本解耦。我们将其形式化为双层优化问题，并通过交替优化求解：内循环使用冻结的评分标准作为廉价代理，以零预言机成本指导技能修改；外循环调用少量预言机 rollout，通过秩相关重新对齐评分标准，摊销预言机成本并稳定文本空间中的更新。在复杂智能体任务基准上的实验表明，与前沿演化方法相比，我们的方法以少 40--70% 的 token 成本优于现有自动技能方法。代码见 https://github.com/WalteR-MittY-pro/SkillLift。

## Abstract
LLM-based agents increasingly rely on persistent skills, i.e., reusable procedural prompts, to adapt without weight updates. Existing skill self-evolution methods directly revise skill text based on execution feedback, but each oracle evaluation requires a full agent rollout, creating a supervision bottleneck that confines search to failure-patching updates. Our key insight is that ranking is a smoother supervision target than absolute outcome regression: identifying which skill is better requires fewer oracle evaluations than predicting exact scores. Building on this insight, we propose SkillLift, which decouples skill search from oracle cost by learning an oracle-aligned rubric as a structured evaluation space. We formalize this as a bilevel optimization problem solved via alternating optimization: an inner loop uses the frozen rubric as a cheap surrogate to guide skill revision at no oracle cost, while an outer loop invokes a small number of oracle rollouts to re-align the rubric via rank correlation, amortizing oracle cost and stabilizing text-space updates. Experiments on complex agent task benchmarks show that our method outperforms existing auto-skill methods with 40--70\% less token cost compared to frontier evolving methods. Codes are available at https://github.com/WalteR-MittY-pro/SkillLift.

- **核心问题**：现有技能自演化方法直接依据执行反馈改写技能文本，但每次 oracle 评估都需要一次完整的智能体 rollout，形成**监督瓶颈**：可评估的候选技能数量极少；而技能文本空间高度不连续，少量 oracle 信号只能驱动保守的「修补失败式」更新。
- **实证依据（图 1 试点研究）**：在 10 个 WildClawBench 任务、10 轮演化、3 个 rollout 种子下，最优—最差技能分数差距始终很大，优化无法规模化；oracle token 消耗远超框架开销且逐轮恶化。
- **关键洞见**：**排序（ranking）比绝对结果回归是更平滑的监督目标**。判断「哪个技能更好」比预测精确分数所需 oracle 评估更少，且对噪声和不可比的绝对分数更鲁棒（相对序仍可保留）。
- **整体含义**：应将技能搜索与 oracle 成本解耦——先学习一个与 oracle 偏好对齐的结构化评估空间（rubric），再用它把稀疏 oracle 反馈转化为密集、可解释的技能改进信号。表 1 显示，只有 SkillLift 同时具备「演化技能 + 代理评估器 + 密集反馈 + O(L) 的 oracle 调用复杂度」（对比方法多为 O(LT)）。

## 2. 方法论

### 2.1 核心思想
- 学习一个**与 oracle 对齐的 rubric** 作为结构化评估空间：rubric 打分只需一次 LLM 调用、无需 rollout，因此可近乎零成本地评估成千上万个候选技能。
- 将技能演化形式化为**双层优化（bilevel optimization）**，并用**交替优化**求解。

### 2.2 双层目标（公式 1）
- 上层（rubric 对齐）：`min_R E_{t∼T}[ D(σ^R_t, σ^O_t) ]`，即最小化 rubric 诱导排序与 oracle 诱导排序之间的差异；`D` 实例化为 `1 − τ`，其中 τ 为 Kendall 秩相关。
- 下层（技能搜索）：`S*(R) = arg max_S E_{t∼T}[ R(S) ]`，即在 rubric 评分下搜索最优技能文本。
- 因为只关心相对顺序、不要求分数校准，每轮少量 oracle 评估即可重新对齐 rubric。

### 2.3 Rubric 结构（公式 2）
- Rubric 由 M 个**二元判据** `{(c_i, p_i)}` 组成：`c_i` 是关于技能行为的 yes/no 问题，`p_i ∈ Z\{0}` 为有符号权重（正为 merit 奖励，负为 flaw 惩罚）。
- Verifier（一个 LLM）在给定 `(t, S_k, R)` 下判定每个判据，得到命中 `h_i(S_k,t) ∈ {0,1}`。
- 归一化分数：`R(S_k) = (Σ p_i h_i − S_min) / (S_max − S_min)`，其中 `S_max = Σ_{p_i>0} p_i`，`S_min = Σ_{p_i<0} p_i`。
- 命中向量 `h(S_k)` 随分数一起给出，使生成器能看到**哪些判据未通过**，从而定向修订。

### 2.4 内循环：Rubric 引导的技能更新（Mode A，零 oracle 成本）
- 每轮外循环维护单个 champion 技能 `S*_{ℓ−1}`；初始 champion 为种子技能。
- Verifier 先用固定 rubric `R_ℓ` 评估 champion，产生命中 `h*_ℓ`。
- 技能生成器 `G`（与被测智能体同 backbone 的 LLM）据 `(t, S*, R, h*, d_{ℓ,k})` 生成 K 个**多样化修订方向** `d_{ℓ,k}`（如策略优化、工具使用策略、错误处理等），形成 K 个候选分支。
- 分支在轮内迭代精修：只有 rubric 分数不下降时才接受修订（`R(bS) ≥ R(S)` 则保留，否则回退）。
- 终止条件：所有分支满足 `R_ℓ(S_{ℓ,k}) ≥ θ_A`，或内循环预算耗尽。Mode A 全程不调用 oracle。

### 2.5 外循环：Oracle 对齐的 Rubric 更新（Mode B）
- 内循环收敛后，用 oracle 评估 K 个精修分支；champion 的先前 oracle 分数可复用，因此只需 K 次新 rollout，排序覆盖 K+1 个技能。
- Verifier 用当前 rubric 对同一批技能打分，得到本地排序 σ^R；计算 Kendall τ（公式 3）。
- 若 `τ ≥ θ_B`，rubric 已对齐；否则由 **rubricator**（LLM）接收两组排序、每技能分数与命中向量及可选 oracle 反馈，修订 rubric：**添加缺失判据、重新加权、移除与 oracle 持续不一致的判据**。迭代直到 `τ ≥ θ_B` 或预算耗尽（保留历史中 τ 最大的版本）。
- Champion 始终由 oracle 分数直接选出，因此即使 rubric 未对齐，也只会降低内循环指导质量，**不会污染最终输出**。
- 设计要点：rubricator 看到的是**系统性偏差模式**（哪些技能被高估/低估），而非单个误判案例，因而能定位责任判据、定向修订。

### 2.6 算法流程（Algorithm 1）
1. `S* ← S_0`；
2. 对 ℓ = 1..L：
   - Mode A：用 R 给 S* 打分，派生 K 个分支；重复精修各技能，直到 `min_k R(S_k) ≥ θ_A` 或内步 ≥ A_max；
   - Mode B：用 oracle 排序 `{S*, S_1..S_K}` 得 σ^O，用 rubric 得 σ^R；当 `τ(σ^R, σ^O) < θ_B` 且修订次数 < B_max 时，rubricator 修订 R 并重打分；
   - `S* ← arg max_S O(S)`；若 `O(S*) ≥ θ_stop` 则停止；
3. 返回 `S*, R`。

## 6. 主要结论与发现

- **全面胜出**：SkillLift 在全部 6 个模型—基准组合中均优于基线，包括 SkillOpt 和 CoEvoSkills 已显著超过静态技能的配置。
- **突破静态技能上限**：相比一次性编写的技能，WildClawBench 提升 +8.8 ~ +11.5 pp，SkillsBench 提升 +16.7 ~ +24.2 pp（1.5–2.8×）；SkillsBench 因确定性验证器提供更清晰的 oracle 信号而增益更大。
- **Token 效率显著**：达到 0.9 通过率分位所需 token 成本降低 **40–70%**（SkillOpt 为 2.62–2.74×，CoEvoSkills 为 2.13–2.22×）。原因是 Mode A 中 rubric 打分仅需一次 LL

M 调用、无需 rollout，而 oracle 评估仅在外循环每轮进行 K 次（复杂度 O(L)），远低于基线的 O(LT)。

- **密集反馈优于稀疏反馈**：由于每个候选技能都能获得「分数 + 命中向量」的密集信号，生成器可定位到具体未通过的判据并定向修订，这解释了为何在相同或更少 token 下仍能持续改进。
- **rubric 对齐的有效性**：去掉 rubricator（即不做 oracle 对齐）后性能显著下降，说明「学习一个与 oracle 偏好一致的结构化评估空间」本身是增益来源，而非仅仅是「用 LLM 当评分器」。
- **排序目标优于回归目标**：以分数回归替代排序对齐会引入校准误差、对不可比分数更敏感，性能下降，印证了「排序是更平滑的监督目标」这一核心假设。
- **可解释性与可迁移性**：演化出的 rubric 由可读的二元判据组成，能显式揭示「什么构成了一个好技能」，并可作为人类审阅与迁移到新任务的中间产物。
- **跨 backbone 稳健**：在 GPT-5.4、GLM-5.1、DeepSeek-V4-Pro 三种 backbone 上结论一致，说明增益来自框架设计而非某一特定模型的能力。
- **Champion 安全机制**：champion 由 oracle 分数直接选出，rubric 未对齐时只会降低内循环指导质量，不会污染最终输出，这保证了方法的鲁棒下界。

- **任务与领域覆盖仍有限**：2 个 benchmark、147 个任务，虽覆盖多领域，但对更开放、更长程或需要多智能体协作的场景尚未验证。

## 8. 结论与启示

- **核心贡献**：SkillLift 提出「学习与 oracle 对齐的 rubric + 双层优化」框架，将技能搜索与昂贵的 oracle 评估解耦——内循环用零 oracle 成本的 rubric 打分驱动密集技能演化，外循环用少量 oracle 评估对齐 rubric，从而在 O(L) 的 oracle 调用复杂度下实现规模化技能自演化。
- **方法论启示**：
  - 在监督信号昂贵时，**相对排序往往比绝对回归更值得追求**；
  - 把「评估器」本身作为可学习对象，用稀疏 oracle 反馈迭代对齐，是缓解监督瓶颈的通用思路；
  - 密集的、可解释的命中向量反馈比单一标量分数更能指导 LLM 生成器定向修订。
- **实践价值**：在 WildClawBench 与 SkillsBench 上全面超越静态技能与现有演化基线，token 成本降低 40–70%，并产出可读、可迁移的 rubric，对构建低成本、可持续自改进的智能体技能库具有直接参考意义。
