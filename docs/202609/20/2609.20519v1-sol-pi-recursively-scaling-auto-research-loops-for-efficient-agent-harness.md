## 摘要
随着编码智能体从有监督的代码补全转向无人值守、全天候的探索，其工作从孤立的预测扩展为包含推理、工具使用和反馈的长轨迹。因此，token 效率对于扩展递归自我改进变得重要。我们在智能体执行框架层采用受 RSI 启发的方法，跨越来越多且多样的环境扩展自动研究循环，以进行智能体执行框架的 rollout。在这种规模下，该过程产生了可复用的改进，这些改进能够迁移到其开发环境之外，推动自动化智能体执行框架发现走向生产级成果。四种机制经过筛选保留下来并构成 SoL-Pi，涵盖动作执行、上下文压缩、观测处理和委托阅读。在 51 项任务的 EdgeBench 评估中，SoL-Pi 在 GPT-5.6 Sol 和 Opus 5 上达到与 Pi 相当的性能，同时将记录的 token 流量降低 44.7-49.0%，并将 API 成本降低约三分之一。换言之，相对于原生 Codex 和 Claude Code 智能体执行框架，估计每小时可节省 8.75-13.50 美元；相对于 Pi，可节省 4.36-5.71 美元。

## Abstract
As coding agents move from supervised code completion to unattended, around-the-clock exploration, their work expands from isolated predictions into long trajectories of reasoning, tool use, and feedback. Token efficiency therefore becomes important for scaling recursive self-improvement. We take an RSI-inspired approach at the harness layer, scaling auto-research loops across increasingly numerous and diverse environments for harness rollouts. At this scale, the process yields reusable improvements that transfer beyond their development setting, moving automated harness discovery toward production-level outcomes. Four mechanisms survive selection and form SoL-Pi, spanning action execution, context compaction, observation handling, and delegated reading. On the 51-task EdgeBench evaluation, SoL-Pi achieves performance comparable to Pi across GPT-5.6 Sol and Opus 5 while reducing recorded token traffic by 44.7-49.0% and API cost by about one third. In other words, estimated hourly savings are \$8.75-\$13.50 relative to native Codex and Claude Code harnesses, and \$4.36-\$5.71 relative to Pi.

# SoL-Pi 论文总结

## 1. 核心问题与整体含义

- **背景**：编码智能体正从受监督的代码补全转向无人值守、全天候的持续探索，其工作形态由孤立预测扩展为包含推理、工具调用与反馈的长轨迹。轨迹越长，token 开销越大，token 效率因此成为递归自我改进（RSI）能否规模化的**一阶系统约束**。
- **现有路线**：效率研究多聚焦于降低"每 token 成本"，如更快注意力核、服务基础设施、量化/压缩、路由到更便宜模型等。
- **本文切入角度**：探索一条**正交路线**——在 **agent harness（智能体执行框架）层**改善 token 使用，即优化模型与环境之间的中介层，无需额外模型训练，可与基础设施层和模型层优化互补。
- **核心困难**：
  - harness 中工具使用、上下文管理、验证、委派、恢复、终止**紧密耦合**，局部有益的改动可能引发下游失败，或把 token 成本转移到后续阶段。
  - 人工检查长轨迹、识别反复出现的失败模式并转化为代码改动，成本高、难跨任务与环境扩展。
- **已有自动化工作的不足**：Meta-Harness 搜索可执行 harness 程序、RHI 迭代精炼 prompt 级智能体循环规范，但已有研究发现演化出的 harness 可能**过拟合搜索任务**，在未见任务上仅带来边际收益。这凸显了**搜索反馈与最终评估必须分离**。
- **整体含义**：论文提出 SoL-Pi，把自动研究组织为"广到深"的漏斗，在约 150 个方向、约 500 个可执行环境上扩展 AI 主导的自动研究，最终发现四项可迁移的效率机制，使自动化 harness 发现向生产级成果靠近。

## 2. 方法论

### 2.1 核心思想：RSI 启发的 harness 自动研究

- 由一个**研究 AI** 观察另一个运行基础 harness 的智能体的执行轨迹，提出候选改动，并在准备好的研究环境中测试；能力门与效率门决定候选是否保留，开发结果指导后续迭代。
- 三条设计原则：
  - **广度与深度**：广度扩展假设覆盖，深度反复实现、审查、加固有前景的候选。
  - **独立验证**：held-out 证据仅在候选冻结后评估，且**永不回流**到搜索，防止把验证失败补丁成任务特定解。
  - **可扩展编排**：隔离的、可丢弃的搜索谱系让漏斗在更多想法与环境上扩展，而不把失败耦合到其他候选。

### 2.2 Broad-to-Deep 搜索流程

- **外层搜索**：起始于 152 个提议方向，分属六个提议家族——context、progress、tools、delegation、prompt and policy、improvement and evaluation。
- **Oracle Analysis**：在分配 rollout 预算前，检查已有开发轨迹，识别基础 harness 中可避免的工作；每个入选方向必须指出具体开销来源并提出对应 harness 改动。
- **内层独立开发**：每个独立搜索遵循常规自动研究循环——提出改动 → 实现 → 运行固定实验 → 检查结果 → 保留/修订/丢弃。并基于 Ralph Loop 扩展出**迭代实现循环**：实现者把候选精炼到满足明确完成标准，随后由**独立审查者**检查，审查失败触发修订。
- **并行分析**：独立 analyzer 各自检查一条轨迹（重复动作、上下文增长、大观测、稀疏诊断信号），由 reducer 合并为候选级摘要，指导下一轮提议。
- **可丢弃谱系**：每次独立搜索是共享 skill 模板的一次性实例，实验复制模板、设定参数、跑完即止，保留候选与证据但丢弃改过的编排代码。广度来自更多隔离循环，深度来自循环内反复精炼。
- **接受规则（双门控）**：
  - 每个能力指标必须保持在**预先声明的容差**内；
  - 候选必须至少改善一个声明的效率指标；
  - 同时通过两门的候选中，保留在声明指标下的**非支配**结果。
  - 能力指标、容差、效率指标在实验前固定，并**严格隔离于优化 agent 的控制**，防止其 gaming 接受标准。
- **冻结与隔离**：机制源码、配置、指标、能力容差、接受规则在 held-out 评估前冻结；EdgeBench 保留用于最终验证，其结果永不回流到自动研究循环；验证失败直接拒绝候选，不触发进一步优化。

### 2.3 四项保留机制

| 机制 | 作用环节 | 关键技术细节 |
|---|---|---|
| **Action Fusion** | 动作执行 | 把文件编辑与随后的测试/构建/运行命令**合并为一个工具请求**，在单次观测中返回两个结果，消除中间模型往返（3 次 API 调用降至 2 次）；需要先检查变更结果才能决定后续命令的场景仍保持分离。 |
| **Online Context Compact** | 上下文压缩 | 以 **plan-step 完成边界**重新判断何时压缩。智能体通过 `update_plan` 维护计划；在每个完成边界，harness 依据已完成步骤间观测到的请求数估算剩余模型请求，并用当前窗口在观测增长率下可容纳的请求数封顶。**成本门**比较预测的输入节省与重写 prompt cache 的额外成本；后续压缩还计入未恢复的重写成本，要求更大节省裕度。门通过或上下文接近窗口上限时调用 Pi 原生压缩。 |
| **ObservationPack** | 观测处理 | 对超过阈值（**10 KiB**）的工具结果本地归档，前**两次** provider 请求仍全量发送；从第三次请求起替换为**稳定 handle + 原始大小 + 完整首尾行短摘录**，智能体可按需通过 handle 检索精确分页；小结果不变。 |
| **Evidence-Preserving Reducer** | 委派阅读 | 压缩来自预定义命令集、≥**4 KiB** 的构建/测试日志；文件读取与搜索结果绕过
